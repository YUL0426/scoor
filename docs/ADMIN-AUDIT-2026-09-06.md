# Scoor 어드민 점검 및 UI/UX 개선

## 판단

로컬 수정 및 검증 완료. 운영 배포 승인을 의미하지 않는다. 운영 환경에서의 쓰기·인증·접근 제한 검증은 남아 있다. 기존 iOS 출시 점검 결과는 `APP-STORE-AUDIT-2026-09-06.md`를 함께 참고한다.

저장소 `YUL0426/scoor`, 작업 브랜치 `feat/release-blockers-2026-08`. 기존 GitHub·Supabase 연결과 환경변수 파일을 유지했다. 운영 DB·인증 설정 변경, 배포, 커밋·푸시는 하지 않았다.

## UI/UX 변경

[Linear의 디자인 개편 설명](https://linear.app/now/behind-the-latest-design-refresh)을 참고해 콘텐츠 중심 계층, 저채도 배경, 간결한 탐색과 얇은 구분선을 적용했다. Scoor의 브랜드 포인트 색은 유지했다.

- 사이드바를 운영·콘텐츠·샘플 미리보기로 구분하고 현재 페이지 표시, 모바일 메뉴를 제공한다.
- 실제 동작하는 ⌘K/Ctrl+K 검색 및 방향키·Enter 페이지 이동을 제공한다.
- 운영 개요의 가짜 DAU·사용자 수를 제거하고 토픽·피드 API 조회 결과로 바꿨다. 집계 범위는 각각 최근 200개로 명시한다.
- 토픽·피드 목록에 검색, 상태 필터, 새로고침, 작성 모달, 성공·실패·빈 상태 안내를 정리했다.
- 피드 삭제는 글 내용이 표시되는 확인창에서 취소 또는 확정한다. 저장 중 중복 조작을 막는다.
- 실제로 지원하지 않는 2FA·자동 검열·자동 발행 등의 가짜 활성 상태를 제거했다. 사용자·분석·알림·월드 아젠다는 샘플임을 표시한다.
- 설정의 연결 상태는 실행 환경에서 확인하는 읽기 전용 표시다. 연결 성공 여부와 설정 존재 여부를 구분한다.

## 발견한 문제와 수정

| 문제 | 조치 및 검증 |
|---|---|
| 조건부 useId, 렌더 중 난수 등 린트 오류 | 훅 호출을 일정하게 유지하고 스켈레톤 폭을 결정적으로 변경. 린트 오류·경고 0 |
| 로그아웃 요청 실패에도 화면 이동 | 성공 응답을 확인한 뒤 이동하도록 수정, 실패 메시지 제공 |
| 세션 토큰 형식·만료 검증 부족 | 추가 토큰 조각·잘못된 만료 값·만료 세션 거부, 현재 관리자 이메일과 대조 |
| 요청 출처 및 입력 검증 부족 | 로그인·로그아웃·데이터 API의 교차 출처 요청 거부, 자격 증명 타입·길이와 UUID 형식 검증 |
| 서버 전용 설정의 경계 불명확 | server-only 적용, 인증 설정 형식 검사, Supabase 요청에 10초 타임아웃 적용 |
| 빠른 이동 Enter 후 재열림, 모바일 상단 잘림 | 기본 키 동작 차단 및 모달 위치 조정. 실제 브라우저에서 재검증 |
| 주 버튼 명암 대비 부족 | 색상 보정. 최종 피드 화면 axe 검사 위반 0 |

## 실제 실행한 검증

- `npm run build`: 성공. 빌드된 앱을 `next start`로 로컬 실행해 화면을 다시 확인했다.
- `npm run lint`: 오류 0, 경고 0.
- `admin/tests/auth-smoke.mjs`: 개발 모드와 운영 빌드에서 각각 HTTP 검사 39건 통과. 비로그인 접근, 잘못된 입력·UUID, 교차 출처, 변조·만료·다른 관리자 세션, 로그인·로그아웃 쿠키를 확인했다.
- 브라우저: QA 로그인, 새로고침 후 세션 유지, 로그아웃 후 보호 페이지의 로그인 리다이렉트, 토픽 초안 작성→공개→마감, 공식 피드 등록→숨김→해제→삭제 취소→삭제 및 새로고침 후 반영을 확인했다.
- 브라우저: 검색 결과 없음, 로컬 백엔드 503 장애 시 오류 안내와 재시도 복구, 빠른 이동, 모바일 메뉴를 확인했다.
- 사용자·분석·알림·월드 아젠다 네 페이지의 렌더링과 샘플 안내를 확인했다. 실제 데이터 기능을 검증한 것은 아니다.
- 1440px 데스크톱 및 390px 모바일 화면을 확인했다. 모바일 가로 넘침 없음, 빠른 이동 창이 화면 안에 배치됨을 측정했다.
- 최종 피드 화면 axe 자동 검사: 위반 0, 수동 판단 필요 항목 2(Radix 닫힌 모달의 참조 및 로고 글자). 전체 접근성 인증이나 스크린리더 검증을 의미하지 않는다.
- 브라우저 런타임 예외 목록은 비어 있었다.
- 실제 `.env.local`의 서비스 역할 키·세션 비밀값·비밀번호 해시가 `.next/static` JavaScript에 포함되지 않았음을 값 출력 없이 검사했다.
- 운영 Supabase는 읽기 전용 요청으로 토픽 6건·피드 0건 응답을 확인했다. 쓰기 테스트는 모두 별도의 로컬 메모리 백엔드를 사용했다.

## 미검증 및 남은 운영 과제

1. 운영 도메인에서의 로그인·Secure 쿠키·프록시 Origin/Host 처리, 실제 관리자 권한 및 배포 환경변수: 미검증. 로컬 성공만으로 운영 성공을 단정하지 않는다.
2. 운영 Supabase 작성·상태 변경·삭제 및 iOS 앱 반영: 미검증. 승인된 테스트 환경/데이터로 종단간 확인이 필요하다. 로컬 모의 백엔드는 PostgreSQL 제약·RLS를 재현하지 않는다.
3. 외부 공개 전 접근 보호를 확인해야 한다. 현재 코드에는 MFA·IP 제한·영속 로그인 속도 제한·관리 작업 감사 로그가 없다. 호스팅 계층에 이미 보호가 있는지도 미검증이다. 단일 관리자 방식이며 개별 세션 서버 폐기는 지원하지 않는다.
4. 사용자·분석·알림·월드 아젠다는 미연동이다. 신고 처리 큐와 자동 검열을 실제 운영 기능으로 사용할 수 없다. 필요한 운영 절차를 별도로 확정해야 한다.
5. 실제 모바일 Safari·스크린리더, 장시간 운영·부하·10초 타임아웃 직접 유발: 미검증.
