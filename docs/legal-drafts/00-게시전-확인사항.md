# Scoor 정책 문서 사용 안내 — 내부 검토용

작성일: 2026년 9월 6일

## 사용 방법

1. `01-개인정보처리방침-초안.md`와 `02-이용약관-초안.md`를 각각 별도 Notion 페이지에 가져오거나 내용을 붙여 넣는다.
2. `[확정 필요: …]` 항목을 실제 운영 정보와 절차로 채운다. 초안 안내와 편집자 주석은 확정 후 삭제한다.
3. 시행일·운영자 연락처·문서 간 링크를 일치시킨다. 이전 버전은 별도 보관한다.
4. 공개할 때는 로그아웃한 브라우저에서도 읽히는지 확인하고 편집 권한을 공개하지 않는다. 이 작업에서는 Notion 게시, 앱 링크 변경, 웹페이지 변경을 수행하지 않았다.

두 문서는 **현재 작업본의 구현을 바탕으로 만든 검토용 초안**이다. 운영 환경의 동작·법적 적합성에 대한 인증 또는 법률 전문가의 최종 검토를 대신하지 않는다. 앱 사용자가 아니라 운영자에게만 필요한 검토 메모는 공개 본문에서 제거한다.

## 반드시 확정할 사항

| 항목 | 필요한 결정·확인 |
| --- | --- |
| 운영 주체 | 개인 또는 사업자의 적법한 명칭, 주소·연락처, 개인정보 담당자 |
| 이용 대상 | 출시 국가, 최소 연령, 만 14세 미만의 허용 여부와 확인·동의 절차. App Store 연령 등급만으로 개인정보 관련 아동 절차를 대체하지 말 것 |
| 처리 근거 | 서비스 계약 이행에 필요한 처리와 선택 동의 처리를 구분. 신고·보안 정보의 근거도 별도 검토 |
| 민감정보 | 감정 기록·자유 입력, 정치 관련 World 참여가 건강정보·정치적 견해 등으로 연결되는 범위 검토. 필요한 별도 동의나 기능 제한은 약관 문구만으로 해결되지 않음 |
| 삭제·보유 | 서버 삭제 표시 데이터, 삭제 댓글, 문의 이력, 인증·API 로그, 백업의 구체적 보유기간과 파기 수단 |
| 수탁·이전 | Supabase 계약 법인, DB 리전, 로그·백업·해외 지원 접근, 재수탁자 및 문의 이메일 제공자 확인. 국내 리전이라는 설명만으로 국외 이전이 없다고 단정하지 말 것 |
| 약관 동의·공지 | 현재 가입 화면의 약관 안내·동의, 공지 수단·기간과 동의 이력. 커뮤니티 가이드라인 동의 이력은 약관·개인정보 동의 전체를 대신하지 않음 |
| 신고 운영 | 실제 처리 담당자·주기, 제한 조치 수단, 통지·이의신청 방법. 현재 어드민의 알림·신고 관련 샘플 화면은 실제 처리 큐가 아님 |

운영 설정을 확인하지 않은 부분은 **미검증**이다. 이번 작업에서는 운영 DB·인증 설정을 변경하거나 실제 계정을 생성·삭제하지 않았다.

## 코드에서 확인한 핵심 차이

- `AuthService.swift`, `AppleSignInController.swift`, `GoogleSignInController.swift`: 이메일 인증과 Apple·Google 인증 경로. Google은 `openid email profile`, Apple은 이름·이메일 요청. 실제 공급자 로그인 성공 여부는 이번 문서 작업에서 미검증.
- `AppServices.swift`, `AccountMigrator.swift`: 개인 기록은 기기 우선 저장 후 로그인 계정으로 동기화. 게스트 기록의 계정 편입이 있으며 닉네임·이모지·소개 업로드 경로가 있다. 모든 프로필 편집의 실시간 서버 동기화를 약속하지 않았다.
- `MockUserService.swift`, `MyPageView.swift`: 이름과 달리 실제 앱에서 쓰는 로컬 프로필 저장소가 있다. 선택 성별·사진은 기기에 저장하며 해당 필드의 서버 업로드는 확인되지 않는다.
- `RemoteScoreService.swift`, `ScoreSyncQueue.swift`: 점수 삭제 시 `deleted_at` 표시를 보내고 이유·감정 값은 비우지만 점수값은 유지한다. “개별 기록 즉시 완전 파기”라고 쓸 수 없다.
- `RemoteFeedService.swift`: 댓글 삭제는 본문을 비우는 삭제가 아니라 삭제 표시 방식이다. 좋아요는 서버에 계정과 함께 저장한다.
- `RemoteWorldService.swift`: World의 익명 옵션은 화면 표시 수준이며 서버에 계정 식별자가 저장된다. 응답·RLS 구조상 이를 재식별 방지 보장으로 표현해서는 안 된다. 현재 제출 호출의 `countryCode`는 nil이며 GPS 수집 경로도 확인되지 않는다.
- `account-delete/index.ts`, DB 외래키: 계정 삭제 시 연결된 운영 테이블 데이터를 연쇄 삭제하는 구조. 실제 운영 삭제·Apple 토큰 폐기·백업 삭제는 미검증이므로 “모든 사본 즉시 완전 삭제”를 약속하지 않았다.
- `PrivacyInfo.xcprivacy`: 추적 없음 및 이메일·사용자 ID·사용자 콘텐츠 선언. 이 파일만으로 실제 App Store Connect 신고가 완성되지는 않는다.
- `AppServices.swift`: 감정 분석기는 비활성화 구현을 사용한다. 외부 AI 전송·진단 기능을 초안에서 제외했다.

기존 `landing/app/privacy/ko/page.tsx`에는 “서울 리전”, “탈퇴 시 즉시 파기”라는 표현이 있지만, 코드의 문구만으로 운영 사실을 확정하지 않았다. 이번 초안에서는 리전·해외 접근·백업을 확인 항목으로 두고 삭제 방식의 차이를 설명했다. 기존 웹페이지는 수정하지 않았다.

## 참고한 공식 자료

- 개인정보 처리방침의 필수 기재사항과 국외 이전은 [개인정보 보호법](https://www.law.go.kr/lsInfoP.do?ancYnChk=0&lsId=011357), 특히 제30조 및 제28조의8의 요건을 기준으로 최종 확인해야 한다. 초안의 계약 이행 근거는 각 처리의 필요성과 실제 절차를 확인한 뒤 확정한다.
- 개인정보보호위원회는 [2026년 4월 개정 개인정보 처리방침 작성지침](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=D010000000&nttId=12018)을 공개하고 있다. 최종 검토 시 해당 지침과 대조할 수 있다. 이번 작업에서는 안내 게시문을 확인했으며 첨부 PDF 전체 검토를 수행한 것은 아니다.
- 책임 면제·일방적인 조건 변경 등은 [약관의 규제에 관한 법률](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=&chrClsCd=010202&efYd=20240209&lsiSeq=253655&urlMode=lsInfoP)을 고려하여 포괄 면책·침묵에 의한 동의 간주 문구를 두지 않았다.
- Supabase는 고객 앱의 이용자 데이터 처리를 자사 사이트 방문자에 관한 방침과 구분한다. 수탁 관계는 [Supabase 개인정보처리방침](https://supabase.com/privacy) 및 [DPA](https://supabase.com/legal/customer-resources/data-processing-addendum), 실제 계약을 확인해야 한다.
- Supabase [로그 문서](https://supabase.com/docs/guides/monitoring-and-debugging/logs)와 [백업 문서](https://supabase.com/docs/guides/platform/backups)는 보유기간이 플랜·기능 설정에 따라 달라짐을 설명한다. Scoor의 실제 플랜을 확인하지 않고 일수를 기입하지 않았다.

공개 정책 본문은 위 자료를 복사한 것이 아니라 Scoor 코드의 데이터 흐름과 확정해야 할 운영 조건을 반영해 작성했다.
