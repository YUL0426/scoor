# 📌 Scoor 수정 보고서

## 1. 작업 요약

- **Score 탭**: 점수 입력 UI(다이얼, 키패드, 슬라이더, 제출 버튼, 사유 입력 시트/단계)를 제거하고, 배경·블러·날짜 문구와 중앙 `scoor` 브랜드만 표시하도록 단순화함. `init(scoreService:userService:)` 시그니처는 유지.
- **World 탭**: 국가/도시 점수를 0–100 **정수**로 표시하도록 통일하고, 맵 버블 `id`와 피드 데이터 키를 명시적으로 맞춤. 상세 화면에서 국가명·평균이 버블과 일치하도록 버블 조회 로직을 보완함.
- **My Page / Statistics**: `ScoreEntry` 기반의 일 단위 단일 모델과 `ScoreCalendarIndex`로 캘린더·통계의 일별 데이터를 정렬하고, 점수 저장 시 알림으로 다른 탭이 다시 로드되도록 함. 캘린더에 reason 존재 여부를 점 인디케이터로 표시.
- **공통**: `MockScoreService` 저장/조회 및 주요 ViewModel에 DEBUG 로그 추가. Preview용 `sampleEntriesByDay` 추가.

## 2. 원인 분석

- **Home**: 설계상 “로고만” 보여야 하는 탭에도 전체 점수 입력 플로우와 사유 시트가 남아 있어 요구사항과 불일치함.
- **World**: 말풍선에 `"7.2"` 등 **0–10 스케일 문자열**이 사용되어 앱 전역의 0–100 정수 규칙과 혼동을 일으킴. 상세 화면의 평균 라벨이 **현재 맵 스코프의 배열에서만** 버블을 찾아, 스코프와 무관하게 푸시된 국가와 어긋날 수 있음. 피드 목록을 **인덱스 기반 `ForEach`**로 갱신해 SwiftUI 식별/갱신이 불안정할 여지가 있음.
- **캘린더 vs Stats**: My Page는 `[Date: Int]`만 보유해 **reason**을 반영하지 못함. 탭 간에는 동일 `scoreService` 인스턴스를 쓰지만, 저장 직후 **재로드 트리거**가 없어 UI가 늦게 맞춰질 수 있음. Stats는 주간/월간 계산용 `Calendar`와 일별 키 생성 시 `startOfDay` 기준이 달라질 경우 조회 키가 어긋날 위험이 있음.

## 3. 수정 내용

- **`ScoreInputView`**: 플로우 enum·다이얼·키패드 시트·사유 레이어·완료 단계 제거. `flowBackground`, 날짜 블록, 중앙 `scoor` 텍스트만 유지. 주입된 서비스는 미사용이어도 컴파일러/린터 경고를 피하기 위해 투명 오버레이 `onAppear`에서만 참조.
- **`Score.swift`**: `ScoreEntry`(calendarDay, score, reason), `ScoreCalendarIndex.entriesByDay(from:calendar:)`, `Notification.Name.scoorScoreStoreDidChange` 정의.
- **`MockScoreService`**: `saveScore` 성공 후 위 알림 브로드캐스트. DEBUG 시 저장·히스토리 조회 로그 출력.
- **`StatsViewModel`**: 일별 맵을 `[Date: ScoreEntry]`로 구축, 조회 시 `Calendar.current`의 `startOfDay`(`dayCal`) 사용. `StatsView`에 `onReceive(scoorScoreStoreDidChange)`로 `load()` 재호출.
- **`MyPageViewModel` / `MyPageView`**: `entriesByDay: [Date: ScoreEntry]`로 전환, `entry(for:)` 제공. 캘린더 셀에 `hasReason` 시 작은 원 표시. 월 평균은 정수(반올림). 동일 알림으로 `load()` 재호출.
- **`WorldViewModel`**: `WorldMapBubble`에 `averageScore: Int`, `displayName`, `scoreText`. 피드 `CountryFeedUserEntry`에 `score: Int`. `bubble(for:)`는 global/local **양쪽**에서 id 검색. `worldAverageLine()`은 글로벌 버블 정수 평균. DEBUG 시 어노테이션 요약 로그.
- **`WorldView`**: `ForEach(..., id: \.id)`, 탭 시 DEBUG 로그, `MapSpeechBubbleButton`은 `scoreText`·`displayName` 사용. `CountryFeedDetailView`는 `ForEach(entries)` + `countryId` `onChange`로 피드 재바인딩, 좋아요는 `entry.id` 기준 토글.
- **`ScoreInputViewModel`**: DEBUG 로그(오늘 점수 로드, 저장 성공).
- **`PreviewData`**: `sampleEntriesByDay` 계산 프로퍼티 추가.

## 4. 데이터 흐름 변경

| 구분 | 변경 전 | 변경 후 |
|------|---------|---------|
| Score 탭 | ViewModel이 서비스로 오늘 점수 로드·입력·저장·사유 | 동일 `AppServices`의 서비스는 주입만 유지, **이 화면에서는 호출 없음** |
| 일별 집계 | My Page: 점수만 `[Date:Int]`, Stats: 튜플 맵 | 공통 **`Score` 히스토리 → `ScoreEntry` / `ScoreCalendarIndex`** |
| 저장 후 UI | 탭 재진입·수동 새로고침에 의존 가능 | **`scoorScoreStoreDidChange`** → Stats·My Page `load()` |
| World | 문자열 점수, 스코프 단일 배열 조회 | **정수 점수**, 버블 **id ↔ feedData 키** 명시, 상세는 **양 스코프**에서 버블 해석 |

## 6. 검증 방법

- **빌드**: Xcode에서 `Scoor` 스킴, 시뮬레이터 대상(예: iPhone 17)으로 `xcodebuild` 실행 시 **BUILD SUCCEEDED** 확인.
- **Score 탭**: 키패드·사유 시트·제출 버튼이 보이지 않고 로고·날짜·배경만 표시되는지 확인.
- **World 탭**: 말풍선·국가 상세·피드 행의 점수가 **소수 없이 정수**인지, 탭한 국가와 상단/평균 라벨이 일치하는지 확인(콘솔에 `[Scoor] World map tap ...` DEBUG 로그 가능).
- **데이터 동기화**: `MockScoreService.saveScore`가 호출되는 경로에서 저장 후 Statistics·My Page 탭으로 전환해 **같은 일자 데이터**가 반영되는지 확인(콘솔 알림·로그 참고). 캘린더에서 reason이 있는 날 **점 인디케이터** 표시 확인.

## 7. 추가 참고사항

- **리스크**: Score 탭에서 점수를 입력·저장하는 UI가 제거된 상태이므로, 실제 기기에서 “홈에서 오늘 점수 입력” 시나리오는 동작하지 않음. 이후 입력 화면을 다른 탭/플로우로 옮기거나 복구할 때 동일 `ScoreServiceProtocol`과 알림 패턴을 재사용하는 것이 좋음.
- **알림 범위**: 현재 `scoorScoreStoreDidChange`는 **`MockScoreService.saveScore`**에서만 발행. 실서비스/API 스토어로 교체 시 동일 시점에 알림(또는 `ObservableObject` 기반 공유 스토어)을 맞춰야 탭 간 일관성이 유지됨.
- **SwiftData `ScoreModel`**: 프로젝트에 컨테이너는 있으나 본 수정에서는 **메모리 목 서비스**가 단일 소스로 사용 중. 향후 SwiftData와 병합 시 `saveScore`/`getScoreHistory` 구현과 알림 발행 지점을 함께 정리할 필요가 있음.
- **미사용 코드**: `ScoreHomeView`, `NumericKeypadSheet`, `ReasonInputSheet` 등은 이번 범위에서 제거하지 않았으며, 정리 시 중복·혼선을 줄이기 위해 검토 가능.
