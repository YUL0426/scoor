# Apple 삭제 검증과 수동 처리

자동 재시도는 비활성화한다. 이 문서는 사람이 실행하는 절차이며 감시 작업을 등록하지 않는다.

## 실제 Apple 계정 출시 전 검증

1. 삭제 가능한 시험 계정으로 실제 iPhone에서 Apple 로그인하고 가입을 완료한다. 운영 서버에 해당 Apple 계정이 존재하는지 확인한다.
2. Scoor 설정 → 계정 및 데이터 삭제를 실행하고 Apple 재인증을 완료한다. 실행 시각을 기록한다.
3. 앱이 로그인 화면으로 돌아오는지, 오류 또는 “Apple 로그인 연결 해제가 아직 완료되지 않았어요” 안내가 나오는지 기록한다.
4. 서버에서 시험 계정과 연결 프로필의 삭제, 폐기 큐 상태를 확인한다. 큐가 비었다는 사실만으로 최초 폐기 성공을 판정하지 않는다.
5. iPhone 설정 → Apple 계정 → Apple로 로그인에서 Scoor 연결이 사라졌는지 확인한다. 검증 전에 직접 연결을 해제하거나 Scoor에 다시 로그인하지 않는다.
6. 앱의 `apple_revoked=true` 응답 또는 Apple 연결 해제 확인과 서버 삭제 증거를 함께 기록한다. 확인하지 않은 항목은 미검증으로 남긴다.

## 자동 재시도 중단 기간의 운영 절차

담당: 출시 운영자. 매일 오전·오후 및 삭제 장애 신고 직후 확인한다. 담당자가 이 확인을 지속할 수 없다면 출시 운영 조건이 충족되지 않은 것으로 본다.

저장소 루트에서 공식 Supabase CLI의 `scoor-release` 프로필로 실행한다. 키 값 입력이나 복사는 필요 없다.

```sh
python3 docs/legal-release/2026-09-15/apple-retry-manual.py status
```

출력은 큐 ID·상태·시각·횟수이며 토큰, 사용자 이메일, 서버 키를 포함하지 않는다. `retry_cron_count`는 0이어야 한다.

| 상태 | 운영자 조치 |
| --- | --- |
| `retry_pending` | 최초 시도 후 실패로 기록된 건. `eligible`이 1 이상이면 아래 명령을 한 번 실행한다. 최초 실패 후 5분, 재실패 후 1시간의 대기 시간을 지킨다. |
| `in_progress`, `retrying` | 진행 중이면 기다린다. `needs_review=true`이면 중단·시간초과 가능성이 있으므로 결과를 조사한다. 강제 재시도하지 않는다. |
| `outcome_unknown`, `pending` | 성공 여부 불명. 실행 시각·함수 로그의 상태 코드·Apple 연결 상태 등으로 결과를 확인한다. `retry_pending`으로 임의 변경하지 않는다. |
| `needs_authorization` | 폐기할 토큰이 없어 재시도 불가. 앱은 Apple 설정에서 연결을 해제할 수 있도록 안내한다. 운영자는 구성·코드 교환 실패를 조사하고 미해결로 기록한다. 계정 삭제 자체를 고객 지원 연락에 종속시키지 않는다. |
| `completed` | 폐기는 완료됐으나 큐 정리가 남았을 가능성. 상태와 토큰 제거 여부를 확인한 뒤 해당 행만 정리한다. |

```sh
python3 docs/legal-release/2026-09-15/apple-retry-manual.py retry
```

한 번에 만기 도래한 `retry_pending` 최대 10건만 처리한다. 일반 계정 삭제 경로는 호출하지 않는다. 성공한 토큰 행은 삭제되고, 실패는 1시간 뒤 다시 처리 가능해진다. 잔여 `eligible` 건은 상태를 확인한 후 같은 명령으로 다음 배치를 처리한다.

HTTP 오류·시간초과 때는 즉시 반복하지 말고 `status`로 결과를 확인한다. 결과 불명 상태를 실패로 간주하지 않는다. 오류 원문·헤더·토큰을 티켓이나 로그에 복사하지 않는다.

수동 호출은 로컬에서 생성한 5분 만료 일회용 nonce를 HTTPS로 직접 전달한다. SQL에는 해시만 들어가고 `pg_net`을 사용하지 않는다. 서버 키를 읽거나 Vault·SQL·HTTP 헤더에 옮기지 않는다.

점검 기록에는 시각, 운영자, 전후 상태별 건수, 완료 건수, 미해결 큐 ID, 다음 확인 시각만 남긴다. 첫 점검에서 원인을 조사하고, 같은 오류가 재발하거나 24시간 안에 해결되지 않으면 담당 개발자에게 전달해 구성/코드 수정 또는 Apple 지원 확인을 진행한다. 자동 재시도를 대신 켜거나 미해결 행을 삭제하지 않는다.
