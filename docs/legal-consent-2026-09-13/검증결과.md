## 구현·검증한 범위

- 가입 흐름 전에 이용약관, 개인정보 안내 확인, 계정 데이터 수집·이용, 연령 요건을 각각 직접 선택. 기본값은 모두 미체크이며 하나라도 빠지면 진행 불가.
- 기존 로그인 계정도 새 버전 동의 확인. 이전 커뮤니티 동의를 새로운 계약·개인정보 동의로 간주하지 않음.
- 한국어·영어 약관/개인정보 전문을 앱에 포함. 설정의 기존 끊어진 외부 링크 대신 원문을 오프라인 열람.
- 공개 게시 시 권리 보유·제한된 콘텐츠 이용허락·가이드라인 별도 체크. 홈 공유 경로도 포함. 서버의 게시 동의 확인은 홈 글, 댓글, World 점수, 토픽 제안에 적용.
- 계정 이용 동의와 공개 게시 동의를 각각 철회 가능. 필수 동의 거부/철회 후에도 계정 관리·로그아웃·계정 삭제 경로 제공. 철회는 기존 콘텐츠의 자동 삭제가 아님.
- 서버가 사용자 ID와 시각을 정하고 동의 종류·문서 버전·원문 SHA-256·언어·요청 ID를 기록. 사용자의 직접 동의 이력 수정 금지. 다른 계정의 이력 조회 차단.
- 요청 재전송은 중복 기록을 만들지 않고, 철회 전의 과거 수락 요청으로 철회를 되돌리지 못함.
- 동의 전 계정 데이터 편입/동기화 차단, 동의 거절 응답으로 미동기화 개인 기록을 폐기하지 않도록 보완.
- 본인 게시물 공유 해제가 기존 RLS에 막히는 문제를 검증 중 발견해 수정. 다른 사용자의 삭제 글을 열람하는 권한을 주지 않음.

## 아직 출시를 막는 구체적 항목

1. **민감정보 별도 동의가 미완성입니다.** 정치적 견해나 건강정보를 실제로 입력·게시·처리하는 경우 이번 계정 동의나 저작권 이용허락으로 갈음할 수 없습니다. 현재 문서의 입력 자제 안내만으로 기술적 제한/적법한 처리 근거를 갖췄다고 볼 수 없습니다. 정치 주제를 일괄 삭제하거나 일상 점수를 전부 의료정보로 취급하지 않고, 실제 입력/참여 경로별 별도 선택 동의·공개 범위·철회를 보완해야 합니다.
2. **보유·파기/국외 처리 고지가 최종 확정되지 않았습니다.** 기존 `docs/legal-release/간소화안-운영기준.md`의 최대 30일 운영 기준을 취소한 것이 아닙니다. 그 정책과 실제 삭제 표식·본문·백업·로그·Gmail 처리 설정의 일치가 필요합니다. 현재 개인정보 원문의 포괄적인 보유 설명을 최종 법정 고지로 공표하지 마세요. 공급자 로그/백업/SMTP/해외 처리 사실을 관리자 설정 및 계약과 대조해야 합니다.
3. **일반 계정 필수 처리와 선택 정보의 구체적 근거를 더 맞춰야 합니다.** 소셜 로그인 제공자가 전달하는 이름/프로필 메타데이터, 선택 사유/소개, 기존 기기 기록의 서버 편입에 대한 항목·목적·기간·거부 영향을 실제 수집과 다시 대조해야 합니다. 방침 전체의 확인 체크가 모든 선택 처리 동의는 아닙니다.
4. **공개 문서와 App Store 표기를 갱신해야 합니다.** 앱 안 원문은 준비했지만 `scoor.app`의 기존 공개 링크 문제, 현재 Notion 공개 문서와의 내용 일치, App Store Connect URL 및 개인정보 수집 유형은 아직 갱신하지 않았습니다. 국가별 연령 요건의 자기 확인 체크만으로 모든 국가의 미성년자 절차를 보증하지 않습니다.
5. **운영 서버 권한 확인과 새 빌드가 필요합니다.** 앱 호스트는 `ebxdbadcejbytixumxrj.supabase.co`이며 CLI에서 접근 가능한 프로젝트는 다른 프로젝트였습니다. 두 브라우저의 대시보드 세션도 로그아웃 상태였습니다. GitHub OAuth 로그인은 자동 승인 검토가 명시적 방식 승인 부족으로 거절했습니다. 다른 프로젝트에 SQL을 적용하거나 우회 로그인하지 않았습니다.

## 운영 적용 순서

1. 관리자 로그인 확인 완료. 로그/인증메일의 상세 처리 경로와 누락된 선행 마이그레이션을 추가 확인. 백업·Custom SMTP 상태는 위 후속 확인 참조.
2. 남은 선택·민감정보 처리, 파기 및 국외 처리 요건을 구현/검증하고 한국어·영어 원문 확정. 원문 수정 시 문서 해시와 서버 허용 버전을 함께 변경하고 재검증.
3. 새 앱의 동의 기능과 운영 SQL을 함께 배포 계획에 반영. 이 SQL을 적용하면 새 동의를 받지 않은 기존 앱의 제출이 차단되므로, 구버전 배포 상태를 확인하고 앱 업데이트 경로를 준비. 운영 계정을 자동 동의 처리하지 않음.
4. 실제 테스트 계정으로 로그인→동의→개인 기록→홈/World 공개→철회→새 제출 차단→삭제를 검증. 실제 사람의 법적 동의를 자동으로 대리 수락하지 않음.
5. 공개 문서 URL, App Store 개인정보 신고, 새 빌드를 맞춘 뒤 심사 제출.
