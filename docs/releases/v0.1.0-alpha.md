# Scoor v0.1.0-alpha

> Phase 1 · Sprint 0–1 · 2026-06-03
> Build: Xcode 26.1.1 · Simulator: iPhone 17 Pro (iOS 26.1)

## Overview

This is the first internal alpha of Scoor. It establishes the core journaling
foundation: a user can record a daily score (a "scoor"), and that score now
**survives app restarts** thanks to a real SwiftData-backed persistence layer.

- **Sprint 0** delivered durable persistence — scores are written to disk via
  SwiftData, keyed by a stable user identity, and verified end-to-end across
  full app restarts.
- **Sprint 1** built the day-to-day journaling loop on top of that foundation —
  editing an existing score, deleting a score from the calendar, and persisting
  the profile bio — each covered by an automated E2E UI test.

The app keeps its existing MVVM architecture and 4-tab shell (Home / Feed /
World / My Page). Authentication, Feed, and World remain mock-backed and were
intentionally out of scope.

## New Features

- **SwiftData score persistence** (`SwiftDataScoreService`) — a drop-in
  `ScoreServiceProtocol` implementation backed by the app-wide
  `ModelContainer`. Scores are written to disk and reloaded on launch.
  Enforces the "one score per calendar day, last write wins" rule.
- **Single shared SwiftData container** — created once in `ScoorApp` and shared
  by both the SwiftUI environment and `AppServices`, so saved scores persist
  reliably.
- **Home recent card → edit flow** — tapping a recent score card on Home opens
  the score sheet in edit mode (`ScoreHomeView(targetDate:)`) for that day's
  entry; saving overwrites it in place.
- **Calendar score deletion** — the calendar day-detail sheet now offers a
  "delete" action with a confirmation dialog, wired through
  `MyPageViewModel.deleteScore(for:)` and `ScoreServiceProtocol.deleteScore`.
- **Profile bio persistence** — `User` gained a `bio` field; the profile editor
  saves it via `UserServiceProtocol.updateBio` and the profile header displays
  it. The bio survives app restarts.
- **End-to-end UI test suites** — `ScoorPersistenceUITests` (Sprint 0) and
  `ScoorSprint1UITests` (Sprint 1) automate the persistence, edit, delete, and
  bio flows.

## Improvements

- **Store-change notifications** — `saveScore` / `deleteScore` broadcast
  `scoorScoreStoreDidChange` so Home, Calendar, and Statistics reload in sync
  after any write.
- **Unified daily aggregation** — Calendar and Statistics now derive their
  day-level data from a single `Score` history via `ScoreEntry` /
  `ScoreCalendarIndex`, including a reason-present dot indicator on calendar
  cells.
- **Consistent score scale** — World map bubbles, country detail, and feed rows
  display scores as 0–100 integers, with bubble IDs explicitly aligned to feed
  data keys.
- **DEBUG instrumentation** — save/load/delete paths log under `#if DEBUG` to
  aid QA traceability.

## Bug Fixes

- **User identity no longer regenerates on launch** — `MockUserService`
  previously minted a fresh `UUID` every launch, orphaning persisted scores
  (which are keyed by `userId`). The current user ID is now persisted in
  `UserDefaults` (`scoor.currentUserId`) so saved scores remain attached to the
  same user across restarts.
- **Calendar / Stats day-key drift** — day lookups now consistently use
  `Calendar.current`'s `startOfDay`, preventing mismatched keys between the
  calendar and statistics views.

## Known Limitations

- **User & guestbook are still mock-backed** — only scores use SwiftData. The
  bio persists via `UserDefaults` today; migrating user data to SwiftData is
  recommended for a future sprint.
- **Score-input UI was removed from the Score tab** earlier in Phase 1; daily
  input now flows through the Home/score sheet. Any path that relied on the old
  Score-tab input no longer applies.
- **Loose test selectors** — `ScoorPersistenceUITests` uses broad selectors
  (e.g. `staticTexts["1"]`) that can be ambiguous if run against state left by
  other tests. They pass reliably from a clean state / in alphabetical order.
- **Auth, Feed, and World remain mock data** — out of scope for Phase 1
  Sprint 0–1.
